bare minimum to get openbsd running

2026-11-22 · openbsd, install

I wanted a small Unix system I could understand, without a desktop environment piled on top of it. By "understand" I mean that when something breaks, I can name the piece that broke. OpenBSD fits that well. The installer is text, the configuration is a handful of plain files, and the base system already includes X, a terminal and a window manager.

This is the shortest path I know from an empty laptop to a usable OpenBSD 7.9 session. By "bare minimum" I mean four things: Wi-Fi, a way to install packages, a terminal, and a window manager. No desktop environment, no panel, no compositor. Everything ships with the base system except two optional packages and, on some laptops, the firmware for the wireless chip.

OpenBSD 8.0 came out in October 2026, and this describes 7.9. On 8.0 the file names have 80 in them, and I can't promise the installer asks the same questions.

The commands below use iwm0 as the wireless interface, because that's the Intel Wi-Fi on my machine. Yours may have another name; the Wi-Fi section shows how to find it.

Before you start
  • A USB stick you're willing to erase.
  • Ethernet, if you can get it. Some wireless chips need firmware that has to be downloaded, so you need the network to get the network.
  • A backup of anything on the laptop's disk. The steps below give the installer the whole disk, and it erases it.
Write the installer to a USB stick

Download install79.img and the SHA256 file from a mirror listed in the installation guide. Check that the download isn't damaged:

sha256sum install79.img
grep install79.img SHA256

The two hashes must be identical. That rules out an accident. It doesn't rule out a dishonest mirror, which can publish a correct hash of the wrong image. If you already have an OpenBSD machine, signify checks the project's signature, which does:

signify -Cp /etc/signify/openbsd-79-base.pub -x SHA256.sig install79.img

Then find the stick and write the image to it. On Linux:

lsblk
sudo dd if=install79.img of=/dev/sdX bs=1M conv=fsync status=progress

Replace sdX with the stick, and use the whole device (sdb), not a partition (sdb1). dd doesn't ask whether you're sure, so read the lsblk output twice. The size column is the easiest way to tell the stick from the internal disk.

Install the base system

Boot from the stick (the boot menu key is usually F12, F9 or Esc, depending on the laptop) and type i for (I)nstall. Most questions show a default in brackets, and Enter accepts it. The ones worth reading:

  • Network: configure em0 (or whatever your Ethernet is called) with autoconf if it's plugged in. Leave Wi-Fi for later.
  • Setup a user? Yes. Make a normal user; you'll do your daily work as that user, not as root.
  • Do you expect to run the X Window System? Yes.
  • Start X with xenodm? If you answer yes, you can skip the rcctl step at the end.
  • Disk: the whole disk with the automatic layout is fine for a first install.
  • Sets: keep the X sets selected (xbase, xshare, xfont, xserv). Without them there's no graphical session, only the console.

When it finishes, reboot and take the stick out. If the installer had a network, it usually fetches the firmware your hardware needs. If it didn't, run doas fw_update once you're on Ethernet (after the next step, so that doas works).

Give your user doas

doas runs one command as root, like sudo. Log in as your normal user and become root:

su -

Check that your user is in the wheel group with id username. Then, still as root, put this one line in /etc/doas.conf:

permit persist :wheel

It means: members of wheel may run commands as root, and after you type your password, doas won't ask again for a few minutes. Exit the root shell and test it. doas whoami should print root.

Connect to Wi-Fi

List the interfaces and find the wireless one:

ifconfig

On my laptop iwm0 is the Intel Wi-Fi and em0 is Ethernet. Bring the wireless one up and scan for networks:

doas ifconfig iwm0 up
doas ifconfig iwm0 scan

To make the connection survive a reboot, it goes in /etc/hostname.iwm0. That file will hold your Wi-Fi password in plain text, so set its permissions before you write the password into it. That way there's never a moment when another user can read it.

doas touch /etc/hostname.iwm0
doas chmod 600 /etc/hostname.iwm0
doas vi /etc/hostname.iwm0

Put these two lines in it:

join "YOUR_SSID" wpakey "YOUR_PASSWORD"
inet autoconf

The first line joins the access point. The second asks DHCP for an IP address, a gateway and DNS servers. Apply it and check each part:

doas sh /etc/netstart iwm0
ifconfig iwm0
netstat -rn -f inet
ping -c 3 1.1.1.1
ping -c 3 openbsd.org

status: active in the ifconfig output only means the laptop is talking to the access point. It doesn't mean anything is talking back.

The order is what saves time. If ping 1.1.1.1 works but ping openbsd.org fails, everything above DNS is fine, so look at /etc/resolv.conf. If both fail, the problem is higher up, such as no address or no default route. Changing nameservers can't fix that, because the packets never get far enough to ask one. (Some networks block ping, so on those a failure here isn't proof.)

Install a couple of comforts

The base system already has a shell, vi and xterm. I added two packages:

doas pkg_add neovim fish

pkg_add already knows which mirror to use, because the installer wrote it to /etc/installurl. Neither package is needed for anything that follows.

Start a graphical session

As your normal user, create ~/.xsession, the script that runs after you log in graphically:

printf '#!/bin/sh\nexec cwm\n' > ~/.xsession
chmod +x ~/.xsession

Then enable the display manager, xenodm, which shows the login screen:

doas rcctl enable xenodm
doas rcctl start xenodm

Log in. You get X, cwm and an empty screen. Ctrl+Alt+Return opens an xterm, Alt+Tab switches windows, and man cwm lists the rest.

The objection: "you could just install a desktop"

You could. doas pkg_add xfce gets you most of the way to one, and if you want a desktop and don't care what it's made of, do that. It's the better choice for that purpose. But then a broken screen could be the fault of any program the desktop brought with it. Here it's X, xenodm, cwm or xterm. With four suspects you can question all of them.

What I took from it

The network is a chain: interface, association, DHCP, address and gateway, DNS. Once I knew the order, debugging stopped being a matter of trying nameservers until one worked. The desktop is a chain too: X draws, xenodm logs you in, cwm manages the windows. Each piece has one job, so when something breaks, I can name the piece. The "c" in cwm is for "calm". With this few features, it can afford to be.

If you want a system you understand, start this small and add things only when you notice they're missing. Further reading, all from the OpenBSD project: networking, X11, cwm(1) and hostname.if(5).
