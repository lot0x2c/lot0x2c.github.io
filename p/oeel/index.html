oeel

oeel is a file tree in an Emacs side window that you edit like text, in the spirit of oil.nvim. Folders open in place, and indentation shows which folder a line is in. Edit the lines, save, and the files on disk change to match. Source on GitHub.

What an edit does
you do this in the drawer saving does this
delete a line (dd) moves the file to the trash
change a name (cw, i, …) renames it
cut a line, paste it under another folder moves it
copy a line, paste it, give it a new name copies it
type a new line (o) creates a file
type a name ending in / creates a folder
type a/b/c.txt creates the folders and the file
indent a line under a folder (>>) moves it into that folder

Nothing touches the disk until you save (:w, C-x C-s or C-c C-c). Saving lists every change and asks before doing any of them.

Install

Needs Emacs 29.1 or newer. nerd-icons adds icons when it's installed, and evil adds the vim keys. The package is called oeel-drawer.

Doom Emacs, in packages.el:

(package! oeel-drawer :recipe (:host github :repo "lot0x2c/oeel"))

Emacs 30, with the built-in use-package:

(use-package oeel-drawer
  :vc (:url "https://github.com/lot0x2c/oeel")
  :bind ("C-c d" . oeel-drawer-toggle))

Emacs 29: M-x package-vc-install RET https://github.com/lot0x2c/oeel.

Use
command what it does
oeel-drawer-toggle show or hide the drawer; hiding keeps open folders and edits
oeel-drawer-focus show the drawer and move into it, onto the file you're in
oeel-drawer-reveal show the drawer with the current file's folders open

No global keys are bound. Inside the drawer every editing key works as usual, because it's a text buffer. On top of that, RET or l opens a file or folder, h closes a folder, - goes up, . makes a folder the root and gh shows dotfiles.

Safety
  • Every change is listed before it happens.
  • Deleted files go to the system trash.
  • Nothing is overwritten: saving refuses a name that already exists, and refuses names with .., ~ or a leading /.
  • Renames go through a temporary folder, so swapping two names (a→b, b→a) works.
  • Buffers visiting a renamed or moved file follow it to its new name.
